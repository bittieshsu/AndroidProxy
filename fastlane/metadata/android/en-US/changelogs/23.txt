- New: the proxy now rebuilds its LAN listeners when their interface addresses change. Previously the listener was bound once at startup and never again, and on some devices turning Wi-Fi off makes the kernel close the listener bound to that address — turning Wi-Fi back on left the proxy reporting "running" while being unreachable, so it had to be restarted by hand. The listening set is now reconciled in place (new addresses bound, vanished ones dropped) without rebuilding the proxy or dropping existing connections
- New: every UDP session teardown is now counted by category (idle timeout, peer closed, local I/O error, protocol error, resource exhaustion, shutdown, unknown) and the counts are written to the engine stats log, so client-side reconnect churn is visible without attaching a debugger
- New: a developer switch on the debug screen turns on a per-session UDP teardown log line. It is off by default and can be toggled at runtime without restarting the proxy

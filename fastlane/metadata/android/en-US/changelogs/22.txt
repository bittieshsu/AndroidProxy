- New: every UDP session teardown is now logged with a reason (idle timeout, peer closed, local send/recv error, epoll error, resource exhaustion) plus the session lifetime — previously every teardown was completely silent, so client-side reconnect churn was invisible from the server
- New: UDP session creation failures (connection quota or slot exhaustion) are logged together with the REP code sent back to the client
- New: a teardown that reaches the cleanup path without a recorded reason is flagged separately, so a missing instrumentation point shows up instead of staying silent
